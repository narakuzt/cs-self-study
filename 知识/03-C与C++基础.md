## 自测题库

### Q03-01 取地址与解引用

- 类型：代码题
- 出处：[N1570 §6.5.3.2 一元 & 与 * 运算符](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)
- 问题：下面打印什么？

```c
#include <stdio.h>
int main(void) {
    int x = 10;
    int *p = &x;
    *p = 20;
    printf("%d %d\n", x, *p);
    return 0;
}
```

- 答案：

```text
20 20
```

`&x` 取出变量 `x` 的地址，存进指针 `p`；`*p` 通过这个地址访问它指向的那块内存。修改 `*p` 就是在修改 `x` 本身，因为它们是同一块内存。

### Q03-02 指针按类型大小移动

- 类型：易错点
- 出处：[N1570 §6.5.6 加法运算符](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)
- 问题：`p + 1` 让地址增加了多少？

```c
#include <stdio.h>
int main(void) {
    int arr[3] = {10, 20, 30};
    int *p = arr;
    printf("%ld %d %d\n", (long)((char *)(p + 1) - (char *)p), *(p + 1), p[2]);
    return 0;
}
```

- 答案：

```text
4 20 30
```

指针加 1 不是地址加 1，而是加上"一个元素的大小"。`int` 通常占 4 字节，所以 `p + 1` 的地址比 `p` 大 4；这也是为什么 `p[i]` 能正确定位到第 i 个元素。

### Q03-03 空指针

- 类型：概念题
- 出处：[N1570 §6.3.2.3 指针](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)
- 问题：空指针和"没有初始化的指针"（野指针）有什么区别？
- 答案：

空指针（`NULL`）是一个明确的、不指向任何对象的值，可以安全地检查（`if (p == NULL)`）。野指针是没有初始化、或者指向的内存已经失效（比如已经 `free` 掉）的指针，它的值是不确定的，看起来"正常"但解引用是未定义行为，可能崩溃，也可能不崩溃但悄悄破坏别的数据，这类问题比空指针更难排查。好的习惯是指针声明时立刻初始化为 `NULL`，释放后立刻把它设回 `NULL`。

### Q03-04 数组名退化为指针

- 类型：易错点
- 出处：[N1570 §6.3.2.1 左值、数组和函数标示符](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)
- 问题：数组名当函数参数传递时，函数里还能用 `sizeof` 知道原数组的元素个数吗？

```c
#include <stdio.h>
void show(int a[]) {
    printf("in show: %zu\n", sizeof(a));
}
int main(void) {
    int arr[5] = {1, 2, 3, 4, 5};
    printf("in main: %zu\n", sizeof(arr));
    show(arr);
    return 0;
}
```

- 答案：

```text
in main: 20
in show: 8
```

在 `main` 里，`arr` 是数组本身，`sizeof` 得到整块内存的大小（5 个 int，每个 4 字节，共 20）。但数组作为函数参数传递时会退化成指向首元素的指针，`show` 里的 `a` 实际上是一个 `int *`，`sizeof(a)` 得到的是指针的大小（这里是 8，64 位系统上指针占 8 字节），信息已经丢失。这就是为什么处理数组的函数通常还要额外传一个长度参数。

### Q03-05 数组与指针的 `sizeof`

- 类型：代码题
- 出处：[N1570 §6.5.3.4 sizeof 和 alignof 运算符](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)
- 问题：直接对数组变量和指向它的指针分别用 `sizeof`，结果一样吗？

```c
#include <stdio.h>
int main(void) {
    int arr[5] = {1, 2, 3, 4, 5};
    int *p = arr;
    printf("%zu %zu %zu\n", sizeof(arr), sizeof(p), sizeof(arr) / sizeof(arr[0]));
    return 0;
}
```

- 答案：

```text
20 8 5
```

`arr` 本身是数组类型，`sizeof(arr)` 是整个数组占的字节数；`p` 是指针类型，`sizeof(p)` 只是指针本身的大小，与它指向的数组大小无关。`sizeof(arr) / sizeof(arr[0])` 是数出数组元素个数的常见写法，但只在数组本身可见的地方有效（比如不能用在退化后的指针上）。

### Q03-06 下标就是指针运算

- 类型：概念题
- 出处：[N1570 §6.5.2.1 数组下标](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)
- 问题：`a[i]` 和 `*(a + i)` 是什么关系？

```c
#include <stdio.h>
int main(void) {
    int arr[3] = {7, 8, 9};
    printf("%d %d %d\n", arr[1], *(arr + 1), 1[arr]);
    return 0;
}
```

- 答案：

```text
8 8 8
```

标准把 `a[i]` 定义为 `*((a) + (i))` 的等价写法，纯粹是指针运算的另一种表示。因为加法可交换，`1[arr]` 和 `arr[1]` 也是等价的（虽然没人会这样写，这里只是用来说明下标本质上就是指针运算）。

### Q03-07 C 字符串以 `\0` 结尾

- 类型：概念题
- 出处：[N1570 §7.1.1 字符串的定义](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)
- 问题：`char s[] = "hi"` 实际占几个字节？`strlen` 数到哪里停？

```c
#include <stdio.h>
#include <string.h>
int main(void) {
    char s[] = "hi";
    printf("%zu %zu\n", sizeof(s), strlen(s));
    return 0;
}
```

- 答案：

```text
3 2
```

C 语言把字符串定义为"以空字符 `\0` 结尾的字符数组"。字面量 `"hi"` 实际存了 `h`、`i`、`\0` 三个字节，所以 `sizeof(s)` 是 3；`strlen` 只数到 `\0` 之前有效字符的个数，是 2。忘记这个 `\0` 是很多缓冲区溢出的根源。

### Q03-08 `strlen` 与 `sizeof` 的区别

- 类型：易错点
- 出处：[N1570 §7.24.6.3 strlen 函数](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)
- 问题：如果把字符数组传给函数（退化成指针），函数里用 `sizeof` 还能得到字符串长度吗？

```c
#include <stdio.h>
#include <string.h>
void show(char *s) {
    printf("sizeof=%zu strlen=%zu\n", sizeof(s), strlen(s));
}
int main(void) {
    char s[] = "hello";
    show(s);
    return 0;
}
```

- 答案：

```text
sizeof=8 strlen=5
```

`s` 在 `show` 里已经是指针（Q03-04 的退化），`sizeof(s)` 只能得到指针本身的大小（8），完全和字符串长度无关；要知道字符串多长，必须用 `strlen` 在运行时逐个字符数到 `\0`。

### Q03-09 结构体与 `.`、`->`

- 类型：代码题
- 出处：[N1570 §6.5.2.3 结构和联合成员](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)
- 问题：`p->name` 和 `(*p).name` 是什么关系？

```c
#include <stdio.h>
struct Point { int x, y; };
int main(void) {
    struct Point pt = {1, 2};
    struct Point *p = &pt;
    printf("%d %d %d\n", p->x, (*p).x, pt.x);
    return 0;
}
```

- 答案：

```text
1 1 1
```

`p->x` 是 `(*p).x` 的简写：先解引用指针得到结构体本身，再用 `.` 取字段。直接持有结构体变量时用 `.`，持有指向结构体的指针时用 `->`。

### Q03-10 修改结构体指针指向的内容

- 类型：代码题
- 出处：[N1570 §6.5.2.3 结构和联合成员](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)
- 问题：通过指针修改结构体字段，原变量会变吗？

```c
#include <stdio.h>
struct Point { int x, y; };
void move(struct Point *p, int dx) {
    p->x += dx;
}
int main(void) {
    struct Point pt = {0, 0};
    move(&pt, 5);
    printf("%d\n", pt.x);
    return 0;
}
```

- 答案：

```text
5
```

传给函数的是结构体的地址（指针），函数内部通过这个地址直接修改的是原来那块内存，所以 `main` 里的 `pt.x` 也跟着变了。如果 `move` 的参数是 `struct Point p`（按值传递），函数内部改的就只是一份拷贝，不会影响调用者。

### Q03-11 结构体的内存对齐

- 类型：易错点
- 出处：[N1570 §6.7.2.1 结构和联合说明符](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)（标准允许成员间存在未命名的填充）
- 问题：一个 `char` 加一个 `int` 的结构体，大小一定是 5 字节吗？

```c
#include <stdio.h>
struct Mixed { char c; int i; };
int main(void) {
    printf("%zu %zu %zu\n", sizeof(char), sizeof(int), sizeof(struct Mixed));
    return 0;
}
```

- 答案：

```text
1 4 8
```

标准允许编译器在结构体成员之间插入填充字节，以满足每个成员的对齐要求（这里 `int` 通常要求 4 字节对齐）。所以 `struct Mixed` 的实际大小往往不是各字段大小的简单相加，而是 8（1 字节的 `c` 后面补了 3 字节的填充）。具体数值可能因平台而异，但一般不小于字段之和。

### Q03-12 `malloc` 与内存泄漏

- 类型：代码题
- 出处：valgrind 官方工具，检测未释放的堆内存
- 问题：申请了内存却忘记 `free`，用 valgrind 能看到什么？

```bash
cat > leak.c <<'C'
#include <stdlib.h>
int main(void) {
    int *p = malloc(sizeof(int) * 3);
    p[0] = 1;
    return 0;
}
C
gcc -g -O0 -Wall -Wextra leak.c -o leak
valgrind --leak-check=full --error-exitcode=1 ./leak > out.txt 2>&1
grep -q "definitely lost" out.txt && echo "报告了泄漏"
```

- 答案：

```text
报告了泄漏
```

`malloc` 申请的内存必须用 `free` 归还，否则程序结束前这块内存一直"占着"却没人能再用（内存泄漏）。valgrind 会在程序运行期间追踪每一次分配，程序结束时报告哪些内存"确实丢失了"（definitely lost），并给出分配它的代码位置。

### Q03-13 补上 `free` 之后

- 类型：代码题
- 出处：valgrind 官方工具
- 问题：加上 `free(p)` 之后，valgrind 还会报告泄漏吗？

```bash
cat > noleak.c <<'C'
#include <stdlib.h>
int main(void) {
    int *p = malloc(sizeof(int) * 3);
    p[0] = 1;
    free(p);
    return 0;
}
C
gcc -g -O0 -Wall -Wextra noleak.c -o noleak
valgrind --leak-check=full --error-exitcode=1 ./noleak > out.txt 2>&1
echo "退出码=$?"
grep -q "definitely lost" out.txt && echo "报告了泄漏" || echo "没有泄漏"
```

- 答案：

```text
退出码=0
没有泄漏
```

正确配对 `malloc` 和 `free` 之后，valgrind 不再报告泄漏，`--error-exitcode=1` 也不会触发（退出码是程序正常退出的 0）。这也是「过关标准」3.2 要求"用 valgrind 确认没有内存泄漏"的检验方式。

### Q03-14 释放后继续使用

- 类型：易错点
- 出处：[N1570 §7.22.3.3 free 函数](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)（标准规定 free 之后指针的值变为不确定）
- 问题：`free(p)` 之后再用 `p` 会怎样？valgrind 能发现吗？

```bash
cat > uaf.c <<'C'
#include <stdlib.h>
int main(void) {
    int *p = malloc(sizeof(int));
    *p = 1;
    free(p);
    *p = 2;
    return 0;
}
C
gcc -g -O0 uaf.c -o uaf
valgrind --error-exitcode=1 ./uaf > out.txt 2>&1
echo "退出码=$?"
grep -c "Invalid write" out.txt
```

- 答案：

```text
退出码=1
1
```

标准规定 `free` 之后指针的值变成不确定，继续读写它指向的内存是未定义行为：可能看起来正常，可能崩溃，也可能悄悄破坏别的数据结构，取决于这块内存有没有被重新分配给别的东西。valgrind 能在这种"非法写入已释放内存"发生的瞬间就报告出来，比程序表现异常后再排查容易得多。

### Q03-15 重复释放

- 类型：易错点
- 出处：[N1570 §7.22.3.3 free 函数](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)（标准规定对已释放的指针再次 free 是未定义行为）
- 问题：对同一个指针 `free` 两次会怎样？

```bash
cat > df.c <<'C'
#include <stdlib.h>
int main(void) {
    int *p = malloc(sizeof(int));
    free(p);
    free(p);
    return 0;
}
C
gcc -g -O0 df.c -o df
valgrind --error-exitcode=1 ./df > out.txt 2>&1
echo "退出码=$?"
grep -c "Invalid free" out.txt
```

- 答案：

```text
退出码=1
1
```

重复释放同一块内存是未定义行为，可能破坏内存分配器内部的记录，导致后续完全不相关的分配或释放出错，这类 bug 往往在很久之后才表现出来。valgrind 能在第二次 `free` 发生的瞬间就报告"非法释放"。防范方法：`free` 之后立刻把指针设为 `NULL`，重复对 `NULL` 调用 `free` 是安全的、什么都不做。

### Q03-16 `malloc` 失败时返回 `NULL`

- 类型：概念题
- 出处：[N1570 §7.22.3 内存管理函数](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)
- 问题：申请内存的代码为什么要检查 `malloc` 的返回值？
- 答案：

标准规定，如果没有足够的内存可以分配，`malloc` 会返回空指针，而不是抛出异常或让程序停下来。如果不检查就直接使用返回值（比如立刻解引用），一旦真的分配失败，就会变成对空指针解引用，导致崩溃，而且崩溃的位置往往离真正的原因（内存不足）很远、不好排查。严谨的代码应该在使用前判断 `if (p == NULL)` 并做相应处理。

### Q03-17 单向链表：插入与遍历

- 类型：代码题
- 出处：[N1570 §6.7.2.1 结构和联合说明符](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)（结构体可以包含指向自身类型的指针）；对应[主题页过关标准 3.2](../课程/03-C与C++基础.md)
- 问题：在链表头部插入节点，最后遍历打印，顺序是什么？

```c
#include <stdio.h>
#include <stdlib.h>
struct Node { int val; struct Node *next; };

struct Node *push_front(struct Node *head, int val) {
    struct Node *n = malloc(sizeof(struct Node));
    n->val = val;
    n->next = head;
    return n;
}

int main(void) {
    struct Node *head = NULL;
    for (int i = 1; i <= 3; i++) {
        head = push_front(head, i);
    }
    for (struct Node *cur = head; cur != NULL; cur = cur->next) {
        printf("%d ", cur->val);
    }
    printf("\n");
    for (struct Node *cur = head; cur != NULL;) {
        struct Node *next = cur->next;
        free(cur);
        cur = next;
    }
    return 0;
}
```

- 答案：

```text
3 2 1
```

结构体里的 `next` 是指向同类型结构体的指针，这样的结构才能串成链表（结构体不能直接包含自身，但可以包含指向自身类型的指针，因为指针大小固定，不需要知道被指对象的完整大小）。每次 `push_front` 把新节点接到旧的头部前面，所以后插入的先被打印出来。释放时要先记下 `next` 再 `free` 当前节点，否则 `free` 之后再读 `cur->next` 就是 Q03-14 的释放后使用。

### Q03-18 链表反转

- 类型：代码题
- 出处：对应[主题页过关标准 3.2](../课程/03-C与C++基础.md)
- 问题：用三个指针原地反转链表，怎么做？

```c
#include <stdio.h>
#include <stdlib.h>
struct Node { int val; struct Node *next; };

struct Node *reverse(struct Node *head) {
    struct Node *prev = NULL, *cur = head;
    while (cur != NULL) {
        struct Node *next = cur->next;
        cur->next = prev;
        prev = cur;
        cur = next;
    }
    return prev;
}

int main(void) {
    struct Node a = {1, NULL}, b = {2, NULL}, c = {3, NULL};
    a.next = &b;
    b.next = &c;
    struct Node *head = reverse(&a);
    for (struct Node *cur = head; cur != NULL; cur = cur->next) {
        printf("%d ", cur->val);
    }
    printf("\n");
    return 0;
}
```

- 答案：

```text
3 2 1
```

反转的关键是在改变 `cur->next` 之前，先用 `next` 保存原来的下一个节点，否则链条就断了、后面的节点找不到了。`prev` 从 `NULL` 开始，逐个把当前节点的指向"掉头"接到前一个节点上，最后 `prev` 就是新的头。

### Q03-19 空指针解引用导致段错误

- 类型：代码题
- 出处：对应[主题页过关标准 3.6](../课程/03-C与C++基础.md)
- 问题：解引用空指针会怎样？

```bash
cat > seg.c <<'C'
#include <stdio.h>
void boom(void) {
    int *p = NULL;
    *p = 42;
}
int main(void) {
    printf("start\n");
    fflush(stdout);
    boom();
    return 0;
}
C
gcc -g -O0 -Wall -Wextra seg.c -o seg

```

- 答案：


对空指针（地址 0）写入，操作系统会因为访问了没有映射的内存而发送 `SIGSEGV`（段错误）信号终止进程。Shell 里进程被信号杀死时，退出码是 128 加信号编号，`SIGSEGV` 是 11，所以是 139（这与主题 0 Q00-32 的 `128+N` 是同一条规则）。

### Q03-22 `new`/`delete` 与 `malloc`/`free`

- 类型：代码题
- 出处：[cppreference.cn：new 表达式](https://cppreference.cn/w/cpp/language/new)
- 问题：C++ 里创建一个对象，用 `new` 和用 `malloc` 有什么本质不同？

```cpp
#include <iostream>
struct Point {
    int x, y;
    Point(int a, int b) : x(a), y(b) { std::cout << "构造 " << x << "," << y << std::endl; }
};
int main() {
    Point *p = new Point(1, 2);
    std::cout << p->x << " " << p->y << std::endl;
    delete p;
    return 0;
}
```

- 答案：

```text
构造 1,2
1 2
```

`malloc` 只分配内存，不知道也不关心里面要放什么类型的数据；`new` 在分配内存之后，还会调用对象的构造函数完成初始化（这里打印了"构造 1,2"），`delete` 在释放内存之前会先调用析构函数。这是 C++ 面向对象的基础：对象的生命周期由构造和析构函数管理，而不只是一块裸内存。

### Q03-26 引用与指针的区别

- 类型：概念题
- 出处：[cppreference.cn：引用声明](https://cppreference.cn/w/cpp/language/reference)
- 问题：`int &r = x;` 和 `int *p = &x;` 有什么不同？

```cpp
#include <iostream>
int main() {
    int a = 1, b = 2;
    int &r = a;
    r = b; // 这是把 b 的值赋给 a，不是让 r 改指向 b
    std::cout << a << " " << b << std::endl;
    return 0;
}
```

- 答案：

```text
2 2
```

引用在定义时必须绑定到一个已存在的对象，之后不能再"改指向"别的对象——`r = b` 只是把 `b` 的值赋给 `r` 所绑定的 `a`，`a` 因此变成了 2。这一点和指针不同：指针可以随时重新赋值指向别的地址，也可以是空指针；引用一旦绑定就固定了，也不能为空。

### Q03-27 构造与析构的顺序

- 类型：代码题
- 出处：[cppreference.cn：非静态成员函数（构造函数、析构函数）](https://cppreference.cn/w/cpp/language/constructor)
- 问题：对象在什么时候构造、什么时候析构？多个对象的顺序是怎样的？

```cpp
#include <iostream>
struct Noisy {
    int id;
    Noisy(int i) : id(i) { std::cout << "构造 " << id << std::endl; }
    ~Noisy() { std::cout << "析构 " << id << std::endl; }
};
int main() {
    Noisy a(1);
    Noisy b(2);
    std::cout << "main 结束前" << std::endl;
    return 0;
}
```

- 答案：

```text
构造 1
构造 2
main 结束前
析构 2
析构 1
```

对象按声明顺序构造；离开作用域（这里是 `main` 结束）时，局部对象按**声明的相反顺序**自动析构，`b` 后声明所以先析构，`a` 后析构。这个自动调用不需要程序员写任何代码去触发。

### Q03-28 RAII：用对象的生命周期管理资源

- 类型：概念题
- 出处：[cppreference.cn：RAII](https://cppreference.cn/w/cpp/language/raii)
- 问题：为什么说"把资源交给一个对象管理"比手动 `new`/`delete` 更安全？

```cpp
#include <iostream>
struct Guard {
    int *p;
    Guard() { p = new int(0); std::cout << "分配" << std::endl; }
    ~Guard() { delete p; std::cout << "释放" << std::endl; }
};
void may_throw(bool fail) {
    Guard g;
    if (fail) throw std::runtime_error("出错了");
    std::cout << "正常完成" << std::endl;
}
int main() {
    try {
        may_throw(true);
    } catch (...) {
        std::cout << "捕获异常" << std::endl;
    }
    return 0;
}
```

- 答案：

```text
分配
释放
捕获异常
```

`Guard` 在构造函数里申请资源，在析构函数里释放。即使 `may_throw` 因为抛出异常而提前"跳出"函数，栈上的局部对象 `g` 仍然会被正常析构（这个过程叫栈展开），资源照样被释放，不需要在每个可能出错的地方手写清理代码。这就是 RAII（用对象生命周期管理资源）的价值：不容易忘记释放，也不怕异常打断正常流程。

### Q03-32 智能指针自动释放

- 问题：用 `unique_ptr` 代替裸指针，还需要手写 `delete` 吗？

```cpp
#include <iostream>
#include <memory>
struct Res {
    ~Res() { std::cout << "释放资源" << std::endl; }
```
