## 概念清单

学完主题 10 后，下面每一条都应能用一两句话解释并举出例子。括号里是对应的题目。

### 建表与约束

- 表由列（字段）组成，每列有类型；主键唯一标识一行（Q10-01）
- `UNIQUE` 约束禁止重复值；`NOT NULL` 禁止空值（Q10-02）
- 外键约束保证引用的数据确实存在，防止"悬空引用"（Q10-03）

### 增删改查

- `INSERT`、`SELECT`、`UPDATE`、`DELETE` 是最基本的四种操作（Q10-04、Q10-05）
- `WHERE` 过滤行，`ORDER BY` 排序，`LIMIT` 限制返回行数（Q10-06、Q10-07）

### 多表查询

- `JOIN` 把多张表按关联字段连接起来查询（Q10-08）
- `GROUP BY` 把行分组，配合聚合函数（`COUNT`、`SUM`、`AVG`）统计每组的结果（Q10-09、Q10-10）
- `HAVING` 是"分组之后"的过滤条件，`WHERE` 是"分组之前"的过滤条件（Q10-11）

### NULL 的特殊性

- `NULL` 表示"未知"或"缺失"，不等于任何值，包括它自己；判断要用 `IS NULL`（Q10-12）
- 聚合函数（如 `COUNT`）通常会跳过 `NULL` 值（Q10-13）

### 索引与查询性能

- 索引像书的目录，能让按某一列查找不必逐行扫描全表（Q10-14）
- 用 `EXPLAIN QUERY PLAN` 查看数据库实际怎样执行一条查询（Q10-15）

### 事务

- 事务把多个操作打包成一个整体：要么全部生效，要么全部不生效（Q10-16）
- `COMMIT` 提交事务，`ROLLBACK` 撤销未提交的修改（Q10-17）

### 安全

- SQL 注入：拼接用户输入到 SQL 语句里可能改变语句原本的逻辑；参数化查询能避免这个问题（Q10-18）

## 自测题库

### Q10-01 主键唯一标识一行

- 类型：代码题
- 出处：[SQLite 文档：CREATE TABLE](https://www.sqlite.org/lang_createtable.html)
- 问题：往有主键的表里插入两行相同的主键值，会怎样？

```python
import sqlite3

con = sqlite3.connect(":memory:")
cur = con.cursor()
cur.execute("CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT)")
cur.execute("INSERT INTO users VALUES (1, 'Alice')")
con.commit()
try:
    cur.execute("INSERT INTO users VALUES (1, 'Bob')")
    con.commit()
except sqlite3.IntegrityError as e:
    print("IntegrityError")
```

- 答案：

```text
IntegrityError
```

主键（Primary Key）唯一标识表里的每一行，数据库会强制保证主键值不重复。这里第二次插入用了已经存在的主键 `1`，违反了这个约束，数据库拒绝执行并报错，而不是悄悄覆盖或插入一行重复主键的数据。

### Q10-02 `UNIQUE` 与 `NOT NULL`

- 类型：代码题
- 出处：[SQLite 文档：约束](https://www.sqlite.org/lang_createtable.html#unique_constraints)
- 问题：`UNIQUE` 约束禁止插入重复值，但是否禁止插入多个 `NULL`？

```python
import sqlite3

con = sqlite3.connect(":memory:")
cur = con.cursor()
cur.execute("CREATE TABLE t (email TEXT UNIQUE)")
cur.execute("INSERT INTO t VALUES ('a@x.com')")
con.commit()
try:
    cur.execute("INSERT INTO t VALUES ('a@x.com')")
    con.commit()
except sqlite3.IntegrityError:
    print("重复值被拒绝")
cur.execute("INSERT INTO t VALUES (NULL)")
cur.execute("INSERT INTO t VALUES (NULL)")
con.commit()
cur.execute("SELECT COUNT(*) FROM t WHERE email IS NULL")
print(cur.fetchone()[0])
```

- 答案：

```text
重复值被拒绝
2
```

`UNIQUE` 约束禁止两行有相同的非空值，这里第二次插入相同的邮箱被拒绝。但按 SQL 标准，`NULL` 表示"未知"，两个"未知"不能被认为是"相同的值"（Q10-12），所以 `UNIQUE` 约束不会阻止插入多个 `NULL`，这里两次插入 `NULL` 都成功了。

### Q10-03 外键约束

- 类型：代码题
- 出处：[SQLite 文档：外键约束](https://www.sqlite.org/foreignkeys.html)
- 问题：往一张表里插入一个"引用了不存在的记录"的外键值，会怎样？

```python
import sqlite3

con = sqlite3.connect(":memory:")
con.execute("PRAGMA foreign_keys = ON")
cur = con.cursor()
cur.execute("CREATE TABLE authors (id INTEGER PRIMARY KEY)")
cur.execute("CREATE TABLE books (id INTEGER PRIMARY KEY, author_id INTEGER REFERENCES authors(id))")
try:
    cur.execute("INSERT INTO books (author_id) VALUES (99)")
    con.commit()
except sqlite3.IntegrityError:
    print("外键约束拒绝了这次插入")
```

- 答案：

```text
外键约束拒绝了这次插入
```

外键约束保证一张表里的某一列，引用的是另一张表里确实存在的主键值，防止出现"指向不存在的记录"的悬空引用（比如一本书的 `author_id` 指向一个根本不存在的作者）。这里 `authors` 表里没有 id 为 99 的记录，插入会被拒绝。SQLite 默认不开启外键检查，需要显式执行 `PRAGMA foreign_keys = ON`。

### Q10-04 基本的增删改查

- 类型：代码题
- 出处：SQL 的四种基本数据操作语句
- 问题：`UPDATE` 和 `DELETE` 分别怎么写？

```python
import sqlite3

con = sqlite3.connect(":memory:")
cur = con.cursor()
cur.execute("CREATE TABLE t (id INTEGER, name TEXT, active INTEGER)")
cur.executemany("INSERT INTO t VALUES (?, ?, ?)", [(1, "a", 1), (2, "b", 1), (3, "c", 0)])
con.commit()
cur.execute("UPDATE t SET active = 0 WHERE id = 1")
cur.execute("DELETE FROM t WHERE active = 0")
con.commit()
cur.execute("SELECT id, name FROM t")
print(cur.fetchall())
```

- 答案：

```text
[(2, 'b')]
```

`UPDATE 表 SET 列=新值 WHERE 条件` 修改满足条件的行；`DELETE FROM 表 WHERE 条件` 删除满足条件的行。这里先把 id=1 的 `active` 改成 0，再删除所有 `active=0` 的行，最终只剩下 id=2 那一行。`UPDATE`、`DELETE` 如果忘了写 `WHERE`，会修改或删除整张表的所有行，需要格外小心。

### Q10-05 `SELECT` 的常见子句顺序

- 类型：代码题
- 出处：SQL 查询语句的标准结构
- 问题：`WHERE`、`ORDER BY`、`LIMIT` 组合使用，先做哪一步？

```python
import sqlite3

con = sqlite3.connect(":memory:")
cur = con.cursor()
cur.execute("CREATE TABLE t (name TEXT, score INTEGER)")
cur.executemany(
    "INSERT INTO t VALUES (?, ?)",
    [("a", 90), ("b", 60), ("c", 85), ("d", 95), ("e", 70)],
)
con.commit()
cur.execute("SELECT name FROM t WHERE score >= 70 ORDER BY score DESC LIMIT 2")
print(cur.fetchall())
```

- 答案：

```text
[('d',), ('a',)]
```

逻辑上先用 `WHERE` 过滤出满足条件的行（score >= 70，排除掉 60 分的 b），再用 `ORDER BY` 对剩下的行排序（`DESC` 表示从大到小），最后用 `LIMIT` 只取前几条。95 分和 90 分是过滤后剩下的行里最高的两个，对应 d 和 a。

### Q10-06 `WHERE` 的条件写法

- 类型：代码题
- 出处：SQL `WHERE` 子句的常见运算符
- 问题：`BETWEEN`、`IN`、`LIKE` 分别怎么用？

```python
import sqlite3

con = sqlite3.connect(":memory:")
cur = con.cursor()
cur.execute("CREATE TABLE t (name TEXT, age INTEGER)")
cur.executemany(
    "INSERT INTO t VALUES (?, ?)",
    [("Alice", 30), ("Bob", 17), ("Charlie", 45), ("Dave", 25)],
)
con.commit()
cur.execute("SELECT name FROM t WHERE age BETWEEN 20 AND 40")
print(sorted(r[0] for r in cur.fetchall()))
cur.execute("SELECT name FROM t WHERE name IN ('Bob', 'Dave')")
print(sorted(r[0] for r in cur.fetchall()))
cur.execute("SELECT name FROM t WHERE name LIKE 'A%'")
print([r[0] for r in cur.fetchall()])
```

- 答案：

```text
['Alice', 'Dave']
['Bob', 'Dave']
['Alice']
```

`BETWEEN a AND b` 是"大于等于 a 且小于等于 b"的简写；`IN (...)` 检查值是否在给定的集合里；`LIKE` 做模式匹配，`%` 匹配任意多个字符（`A%` 表示"以 A 开头"）。这些写法本质上都可以用更基础的比较和逻辑运算符表达，但更简洁、意图更清楚。

### Q10-07 排序时 `NULL` 排在哪里

- 类型：易错点
- 出处：[SQLite 文档：ORDER BY](https://www.sqlite.org/lang_select.html#the_order_by_clause)（SQLite 中 NULL 在升序时排最前）
- 问题：一列里有 `NULL`，`ORDER BY` 会把它排到哪？

```python
import sqlite3

con = sqlite3.connect(":memory:")
cur = con.cursor()
cur.execute("CREATE TABLE t (name TEXT, score INTEGER)")
cur.executemany("INSERT INTO t VALUES (?, ?)", [("a", 90), ("b", None), ("c", 60)])
con.commit()
cur.execute("SELECT name FROM t ORDER BY score")
print([r[0] for r in cur.fetchall()])
```

- 答案：

```text
['b', 'c', 'a']
```

不同数据库系统对"`NULL` 在排序里算最大还是最小"的默认规则不完全一致：SQLite 里升序排序时 `NULL` 排在最前面（相当于被当作比任何值都小）；有些系统（如 PostgreSQL）默认相反，把 `NULL` 排在最后。写跨数据库的代码时，如果排序结果里 `NULL` 的位置很重要，最好显式用 `NULLS FIRST`/`NULLS LAST`（如果所用的数据库支持）来明确指定，不要依赖默认行为。

### Q10-08 `JOIN` 连接多张表

- 类型：代码题
- 出处：[SQLite 文档：JOIN](https://www.sqlite.org/syntax/join-clause.html)
- 问题：两张有关联关系的表，怎样一起查询？

```python
import sqlite3

con = sqlite3.connect(":memory:")
cur = con.cursor()
cur.execute("CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT)")
cur.execute("CREATE TABLE orders (id INTEGER PRIMARY KEY, user_id INTEGER, amount INTEGER)")
cur.executemany("INSERT INTO users (name) VALUES (?)", [("Alice",), ("Bob",)])
cur.executemany(
    "INSERT INTO orders (user_id, amount) VALUES (?, ?)", [(1, 100), (1, 200), (2, 50)]
)
con.commit()
cur.execute(
    "SELECT users.name, orders.amount FROM users JOIN orders ON users.id = orders.user_id ORDER BY orders.amount"
)
print(cur.fetchall())
```

- 答案：

```text
[('Bob', 50), ('Alice', 100), ('Alice', 200)]
```

`JOIN ... ON 条件` 把两张表按关联字段（这里是 `users.id` 等于 `orders.user_id`）拼接起来，结果里每一行都同时包含两张表的数据。这就是关系型数据库"把数据拆到多张表、需要时再连接查询"的基本用法，而不是把所有信息都塞进一张宽表。

### Q10-09 `GROUP BY` 与聚合函数

- 类型：代码题
- 出处：[SQLite 文档：聚合函数](https://www.sqlite.org/lang_aggfunc.html)
- 问题：怎样统计每个用户一共下了多少订单、总金额多少？

```python
import sqlite3

con = sqlite3.connect(":memory:")
cur = con.cursor()
cur.execute("CREATE TABLE orders (user_id INTEGER, amount INTEGER)")
cur.executemany(
    "INSERT INTO orders VALUES (?, ?)", [(1, 100), (1, 200), (2, 50), (1, 50)]
)
con.commit()
cur.execute(
    "SELECT user_id, COUNT(*), SUM(amount) FROM orders GROUP BY user_id ORDER BY user_id"
)
print(cur.fetchall())
```

- 答案：

```text
[(1, 3, 350), (2, 1, 50)]
```

`GROUP BY 列` 把行按这一列的值分成若干组，`COUNT`、`SUM`、`AVG`、`MAX`、`MIN` 这些聚合函数分别对每一组单独计算，而不是对整张表算一个总值。这里用户 1 有 3 笔订单、总金额 350，用户 2 有 1 笔订单、总金额 50，分组统计的结果一行对应一个用户。

### Q10-10 `AVG`、`MAX`、`MIN`

- 类型：代码题
- 出处：[SQLite 文档：聚合函数](https://www.sqlite.org/lang_aggfunc.html)
- 问题：求一组分数的平均分、最高分、最低分？

```python
import sqlite3

con = sqlite3.connect(":memory:")
cur = con.cursor()
cur.execute("CREATE TABLE scores (v INTEGER)")
cur.executemany("INSERT INTO scores VALUES (?)", [(60,), (80,), (100,), (90,)])
con.commit()
cur.execute("SELECT AVG(v), MAX(v), MIN(v) FROM scores")
print(cur.fetchall())
```

- 答案：

```text
[(82.5, 100, 60)]
```

不加 `GROUP BY` 时，聚合函数把整张表（或整个查询结果）当作一组来计算：`AVG` 是平均值 `(60+80+100+90)/4=82.5`，`MAX`、`MIN` 分别是最大值和最小值。

### Q10-11 `HAVING` 是分组后的过滤

- 类型：易错点
- 出处：[SQLite 文档：结果行的生成（含 HAVING 的处理）](https://www.sqlite.org/lang_select.html#generation_of_the_set_of_result_rows)
- 问题：想找出"订单总额超过 150"的用户，为什么不能直接写 `WHERE SUM(amount) > 150`？

```python
import sqlite3

con = sqlite3.connect(":memory:")
cur = con.cursor()
cur.execute("CREATE TABLE orders (user_id INTEGER, amount INTEGER)")
cur.executemany(
    "INSERT INTO orders VALUES (?, ?)", [(1, 100), (1, 200), (2, 50)]
)
con.commit()
cur.execute(
    "SELECT user_id, SUM(amount) FROM orders GROUP BY user_id HAVING SUM(amount) > 150"
)
print(cur.fetchall())
```

- 答案：

```text
[(1, 300)]
```

`WHERE` 在分组之前对每一行单独过滤，这时候还没有"每组的总和"这个概念，写 `WHERE SUM(amount) > 150` 在大多数数据库里会报错。`HAVING` 是专门给分组之后使用的过滤条件，可以引用聚合函数的结果。简单记忆：先 `WHERE` 挑行，再 `GROUP BY` 分组、算聚合，最后 `HAVING` 挑组。

### Q10-12 `NULL` 不等于任何值

- 类型：易错点
- 出处：[SQLite 文档：NULL 的处理](https://www.sqlite.org/nulls.html)
- 问题：`WHERE b = NULL` 能找出 `b` 是 `NULL` 的行吗？

```python
import sqlite3

con = sqlite3.connect(":memory:")
cur = con.cursor()
cur.execute("CREATE TABLE t (a INTEGER, b TEXT)")
cur.execute("INSERT INTO t VALUES (1, NULL)")
cur.execute("INSERT INTO t VALUES (2, 'x')")
con.commit()
cur.execute("SELECT * FROM t WHERE b = NULL")
print("用 = NULL 匹配到:", cur.fetchall())
cur.execute("SELECT * FROM t WHERE b IS NULL")
print("用 IS NULL 匹配到:", cur.fetchall())
```

- 答案：

```text
用 = NULL 匹配到: []
用 IS NULL 匹配到: [(1, None)]
```

SQL 里 `NULL` 表示"未知"，任何值和 `NULL` 做 `=` 比较，结果既不是真也不是假，而是"未知"（不满足 `WHERE` 条件），包括 `NULL = NULL` 也是"未知"，不是真。所以 `WHERE b = NULL` 永远匹配不到任何行，哪怕真的有 `NULL` 值。要判断一列是否为 `NULL`，必须用专门的 `IS NULL`（或 `IS NOT NULL`）。这是初学者极容易踩的坑。

### Q10-13 聚合函数跳过 `NULL`

- 类型：易错点
- 出处：[SQLite 文档：聚合函数](https://www.sqlite.org/lang_aggfunc.html)（COUNT(列) 不计入 NULL，COUNT(*) 计入）
- 问题：`COUNT(*)` 和 `COUNT(某一列)` 结果一样吗？

```python
import sqlite3

con = sqlite3.connect(":memory:")
cur = con.cursor()
cur.execute("CREATE TABLE t (a INTEGER, b TEXT)")
cur.execute("INSERT INTO t VALUES (1, NULL)")
cur.execute("INSERT INTO t VALUES (2, 'x')")
con.commit()
cur.execute("SELECT COUNT(*), COUNT(b) FROM t")
print(cur.fetchall())
```

- 答案：

```text
[(2, 1)]
```

`COUNT(*)` 数的是行数，不管某一列是不是 `NULL`，这里是 2 行。`COUNT(列名)` 只统计这一列**非** `NULL` 的行数，`b` 这一列有一行是 `NULL`，所以 `COUNT(b)` 是 1。这个差异容易被忽略，写统计代码时要想清楚自己到底要哪一种计数。`SUM`、`AVG` 等聚合函数在计算时也会忽略 `NULL`，而不是把它当作 0。

### Q10-14 索引避免全表扫描

- 类型：代码题
- 出处：[SQLite 文档：EXPLAIN QUERY PLAN](https://www.sqlite.org/eqp.html)
- 问题：没有索引和有索引，同一条查询的执行方式有什么不同？

```python
import sqlite3

con = sqlite3.connect(":memory:")
cur = con.cursor()
cur.execute("CREATE TABLE t (id INTEGER, name TEXT)")
cur.execute("EXPLAIN QUERY PLAN SELECT * FROM t WHERE name = 'x'")
before = cur.fetchall()[0][3]
cur.execute("CREATE INDEX idx_name ON t(name)")
cur.execute("EXPLAIN QUERY PLAN SELECT * FROM t WHERE name = 'x'")
after = cur.fetchall()[0][3]
print("SCAN" in before, "SEARCH" in after and "idx_name" in after)
```

- 答案：

```text
True True
```

没有索引时，数据库只能"逐行扫描"整张表来找出满足条件的行（`SCAN`），表越大越慢。建立索引后，数据库能直接"查找"到目标数据的位置（`SEARCH ... USING INDEX`），不需要看过所有行，类似字典有了目录就不用从头翻到尾。索引不是免费的：它会占用额外的存储空间，并且每次写入（插入、更新、删除）都要多维护一份索引，所以不是所有列都应该建索引，通常只给经常出现在查询条件里的列建。

### Q10-15 用 `EXPLAIN QUERY PLAN` 观察执行方式

- 类型：概念题
- 出处：[SQLite 文档：EXPLAIN QUERY PLAN](https://www.sqlite.org/eqp.html)
- 问题：一条查询跑得慢，怎样知道数据库到底是怎么执行它的？
- 答案：

在查询语句前面加上 `EXPLAIN QUERY PLAN`（不同数据库系统命令名略有差异，PostgreSQL 是 `EXPLAIN`，MySQL 也是 `EXPLAIN`），数据库会返回它打算怎样执行这条查询的说明，而不是真的执行它：用没用到索引、是全表扫描还是索引查找、多表连接的顺序是什么，都能从这份"执行计划"里看出来。这是排查慢查询问题的第一步：先看执行计划，找到哪一步在做代价高的全表扫描，再考虑是否需要加索引或改写查询，而不是凭感觉瞎猜。

### Q10-16 事务：要么全部生效，要么全部不生效

- 类型：概念题
- 出处：事务的 ACID 特性中的"原子性"（Atomicity）
- 问题：转账要同时"扣一个账户的钱、加另一个账户的钱"两步，如果中途系统崩溃，会不会出现钱凭空消失或多出来的情况？
- 答案：

如果这两步操作被包在同一个事务里，数据库能保证"原子性"：这个事务要么完整地全部生效，要么（比如中途崩溃、出错）完全不生效，不会出现"只扣了钱没加上"这种中间状态。事务提交之前，所有的修改都只是"暂定"的，任何一步失败都可以撤销回事务开始之前的状态（见 Q10-17 的 `ROLLBACK`）。这也是转账、下单扣库存这类"必须要么都做要么都不做"的操作，一定要放在同一个事务里的原因。

### Q10-17 `COMMIT` 与 `ROLLBACK`

- 类型：代码题
- 出处：[Python 官方文档：sqlite3 — 事务控制](https://docs.python.org/zh-cn/3/library/sqlite3.html#transaction-control)
- 问题：修改数据后不 `commit`，直接 `rollback`，会怎样？

```python
import sqlite3

con = sqlite3.connect(":memory:")
cur = con.cursor()
cur.execute("CREATE TABLE t (v INTEGER)")
con.commit()  # 建表先提交
cur.execute("INSERT INTO t VALUES (1)")
con.rollback()
cur.execute("SELECT COUNT(*) FROM t")
print(cur.fetchone()[0])
```

- 答案：

```text
0
```

`INSERT` 之后如果没有 `commit`，这次修改还只是这个事务里的"暂定"状态；`rollback()` 把这个未提交的事务整个撤销，数据回到事务开始之前的样子，插入的那一行没有真正生效。只有 `commit()` 才会把修改永久写入数据库。这也是为什么很多数据库连接默认开启"自动提交"，容易让人忽略"没提交就不算数"这件事。

### Q10-18 SQL 注入与参数化查询

- 类型：代码题
- 出处：[Python 官方文档：sqlite3 — 如何使用占位符绑定值](https://docs.python.org/zh-cn/3/library/sqlite3.html#how-to-use-placeholders-to-bind-values-in-sql-queries)（明确建议不要用字符串格式化拼接 SQL）
- 问题：直接把用户输入拼接进 SQL 语句字符串，会有什么风险？

```python
import sqlite3

con = sqlite3.connect(":memory:")
cur = con.cursor()
cur.execute("CREATE TABLE users (name TEXT, secret TEXT)")
cur.execute("INSERT INTO users VALUES ('admin', 'topsecret')")
con.commit()

malicious_input = "x' OR '1'='1"

# 危险写法：直接拼接字符串
query = f"SELECT * FROM users WHERE name = '{malicious_input}'"
cur.execute(query)
leaked = cur.fetchall()

# 安全写法：用占位符参数化
cur.execute("SELECT * FROM users WHERE name = ?", (malicious_input,))
safe = cur.fetchall()

print(len(leaked) > 0, safe)
```

- 答案：

```text
True []
```

直接拼接字符串时，`malicious_input` 里的 `'` 和 `OR '1'='1` 改变了 SQL 语句原本的结构，让条件变成"永远为真"，泄露了本不该被查到的数据——这就是 SQL 注入。参数化查询（用 `?` 占位符，把实际值通过第二个参数传给 `execute`）能杜绝这个问题：数据库驱动会把参数当作纯粹的数据值处理，不管它长什么样都不会被解释成 SQL 语法的一部分，这里恶意输入被当作一个完整的字符串去匹配 `name`，自然查不到任何结果。任何时候把外部输入拼进 SQL 语句，都应该用参数化查询，而不是字符串拼接或格式化。
